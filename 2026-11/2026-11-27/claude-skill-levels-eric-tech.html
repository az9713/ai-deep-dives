The Seven Levels of Claude Skills

Based on Eric Tech’s YouTube video. The screenshots show its transcript panel.

Level 0 Level 1 Level 2 Level 3 Level 4 Level 5 Level 6 What’s Next

Eric Tech’s framework starts at Level 0 and ends at Level 6. The first levels show how to capture a workflow, the middle levels show how to package or borrow expertise, and the last level asks whether the skill still earns its place. Eric’s default is Level 2. Do a real task with Claude, capture your corrections, then turn the finished workflow into a skill. Eric Tech’s video

A skill is a reusable folder centered on a SKILL.md file. Its description tells Claude when it may be relevant. The file can point to supporting instructions, examples, templates, or scripts that Claude loads as needed. That makes the description part of how the skill works. It should name the tasks that ought to trigger it. Skill basics · 1:38 · Claude Code skills documentation

Level 0 · Write it by hand

Write the SKILL.md yourself. You specify when the skill applies and what Claude should do. Eric treats manual authoring as the baseline and moves quickly to letting Claude draft the file. Writing one tiny skill by hand is a practical way to learn which instructions belong in the description and which belong in the body. Levels 0 and 1 · 3:07

Level 1 · Start with Skill Creator

Use Anthropic’s Skill Creator when you already know the job you want Claude to repeat. Describe the inputs and the result, then give it a few strong examples. Eric’s example is a consultant who wants a one-page proposal based on call notes. A few proposals the consultant actually likes give Claude a concrete target for structure and tone. Skill Creator example · 3:13 · Anthropic’s custom-skills guide

Level 2 · Do the job once and capture it

Tell Claude at the start that you want it to track your corrections. Do the real job together and correct the output as you go. When you have a result you would use, ask Skill Creator to turn the workflow and the reusable corrections into a skill. Eric suggests updating the skill as new cases reveal gaps. A useful rule is to include a correction only when it should carry over to another run. Level 2 · 3:40

Example for a video tutorial. If you correct Claude because a claim came from the video description, capture the rule that each explanation needs a caption passage at a specific timestamp. If a correction applies only to this creator or episode, keep it with that job.

Level 3 · Record the workflow in Cowork

Use this when a workflow is easier to demonstrate on screen. In Cowork, open the composer’s + menu and choose Record a skill, then perform and narrate the task. Claude drafts a skill for you to review. Eric’s example is a recurring job on a supplier website that lacks a direct Claude integration. Anthropic documents the recorder for Claude for Mac and advises keeping passwords and sensitive material out of the recording. Level 3 · 4:55 · Anthropic’s recording instructions

Level 4 · Give Claude knowledge it can reuse

Eric uses the word “skill” for three kinds of reusable context. Each solves a different problem. Level 4 · 5:21

  • Data. Point Claude to a source of facts it can consult, such as customers’ purchase histories. The information can stay in its source while the skill tells Claude where and how to look.
  • Artifact standards. Package brand colors, fonts, or templates so that documents and other deliverables follow the same conventions.
  • Definitions. Explain a term or interaction pattern you use repeatedly. Eric cites Matt Pocock’s grill-me, which interviews you about a plan one question at a time.

Level 5 · Adopt and adapt an existing skill

Eric starts with Anthropic’s skill library or Vercel’s skills.sh directory and looks for a skill that already handles the job. Read its instructions and inspect any bundled scripts before enabling it, then adjust it to match your inputs and workflow. The shared format makes skills easier to move between tools. A skill that calls particular tools or scripts still depends on those being available in your setup. Level 5 · 8:12 · skills.sh directory

Level 6 · Test the skill against plain Claude

Pick a recurring task. Run it once with the skill enabled and once with it disabled. If the skill consistently helps, keep it. If the output is as good or better without it, trim or retire it. Eric uses “hobbling” for the case where old instructions hold back a more capable model. You can run the comparison without deleting files. Level 6 · 8:40 · The skill test · 9:12

For a more reliable comparison, use fresh sessions with the same model, prompt, files, and available tools. Change only the skill. Score a few tasks you did not use to write the skill and record factual errors, missing requirements, and minutes of cleanup. Check separately whether Claude chooses the skill on eligible prompts. A skill can produce excellent work when explicitly invoked and still fail to activate on its own.

What's Next

Use your next YouTube tutorial as a Level 2 exercise. Capture the requirements that recur, including timestamped support for every substantive claim and a clear distinction between video frames and caption screenshots. Then run Level 6 on three different videos. Measure whether the skill reduces verification and cleanup time without increasing unsupported claims. Reuse the same videos when you change models so you can see whether the skill still pays for itself.
