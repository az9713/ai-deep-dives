1Why rewrite at all

2023: Messages API written in Python, "basically a request forwarder". Shared deps with research and inference libraries made it hard to move. [A]

Traffic grew ~1,800x (early 2024 to fall 2026). Python overhead on every object alloc, free and task handoff, per token. [A][R]

Incremental first: Rust output parser called from Python. CPU -8 to 10%, but each token now crossed the language boundary 3 times. Not worth the complexity. [A][R]

Full fork-and-rewrite: Claude wrote the core request path in ~1 week. By May 2026 Claude wrote >80% of code Anthropic merged. [A][R]

Generation got cheap. Verification became the bottleneck. [A][R]

2024 quote from the team: "We are not rewriting the API in go or rust!" The economics flipped once code generation stopped being the cost driver. [A]

Why ~700 integration tests could not be the verifier [A][R]

  • Coupled: tests ran Python in-process with Python mocks (billing, rate limits). Claude ported code and tests together, so a pass could mean a weakened test. Audit: >100 weakened assertions.
  • Incomplete: 20 binary flags = 2^20 ≈ 1.05M configs ≈ 12 days at 1 s each, per model, before varying prompts.
  • April 2026: Rust passed ~98% of tests but only ~24% of production inputs matched.

3Turning production into the verifier

Shadowing: a thin Python front door serves every request from Python and runs a shadow copy through Rust; compare both on the way in and out. [A][R]

Nondeterminism + billing: run the model once, replay its output into Rust. Any difference is then in the code, not the model, and the customer is billed once. [A][R]

Privacy: nobody may read requests or replies, and the Python side kept changing. Record the shape of each difference, never its text. [A][R]

Checkpointing: compare every stage (validate, resolve settings, build prompt, call model, sort output, stream, count usage) piece by piece; the first divergence localizes the bug. Record (made-up values):

step: build prompt
piece: 2
first diff: byte 17
python: 190 B
rust: 190 B

[A][R]

Fingerprint = step + piece + first-diff offset + length gap (+ hash). One bug leaves the same mark on every request it touches, so hundreds of thousands of records collapse into a handful of bugs. Fixing dominant fingerprint A revealed hidden B and C. [A][R]

Dispatch: a script every 10 to 30 min groups records and alerts a coordinator Claude only on a new kind; it assigns one worker agent per kind and opens a Slack thread humans can steer. [A][R]

4Three nested verification loops

Each loop catches what the one inside it misses. Read inner to outer. [A][R]

  1. Gets only the fingerprint; hypothesizes a cause from the code (e.g. Rust orders JSON keys differently). [A][R]

  2. Writes its own request or fake-model reply to trigger it, and can read both results in full. [A][R]

  3. Sandbox holds both codebases. Input check builds each prompt with no model call (<1 s). Output check runs both against a fake model. [A][R]

  4. Same difference as the record? No: wrong guess, try again. Yes: edit the Rust until both match. [A]

  5. Add a test that fails on old code and passes on new; open a PR. [A][R]

No match on step 4: wrong guess, return to step 1.

PR from step 5 crosses the seam

Human gate at the seam: PR review [A][R]

Engineers judge fixes, not guesses, and what no verifier can: bug or deliberate change?

Case: web-search tool text was missing in Rust. An agent copied it into files; prompts matched, verifier passed. Engineer: "throwaway code. Abandon that PR."

Merge, deploy to a test environment, then production. Watch shadowed live traffic for the bug's fingerprint. [A][R]

Compare builds with vs without the fix on requests of the same kind (model, caching, tools, thinking). Gone on repeated checks: close. Still there: back to the inner loop with new evidence. [A][R]

Fingerprint persists: return to the inner loop with new evidence.

Reviewer corrections at the seam feed this loop

Correction becomes a rule in CLAUDE.md that every new agent reads first. After one agent guessed at Python's behavior: "port exactly what Python did." [A][R]

Backward sweep: an agent checks existing code against the new rule; found 7 more places the port relied on a guess. [A][R]

Known-bug memory: the rejected web-search shortcut became a note; later records with new fingerprints were linked to it instead of spawning new workarounds. [A]

June: an agent grouped ~60 review comments into proposed rules; an engineer edited and approved them. [A]

Permanent checks: drift tests, lints banning flagged patterns, a merge check forcing a matching Rust change for any Python change. [A][R]

Rules and checks constrain every later agent in the inner loop.

6Humans move to the outer loops

Inside the inner loop: engineers ran Claude and chased differences themselves. [A][R]

At the seam: steering agents and reviewing fixes in Slack. [A][R]

At the edge: writing the rules and checks agents work within. [A][R]

From directing Claude to Claude directing itself; humans for important judgment calls. [A]

Osmani's frame [O] (Ray quotes it [R]): agents run the inner loop; engineers own the outer loop. The human sits in the constraints loop (inputs, architectures, instructions, invariants), the sampling loop, the audit loop and the ownership loop. A loop is investigate, implement, verify, repeat, where an independent check, not the model's say-so, decides done. Quality checks produce evidence; evidence feeds a Verdict; Answerability means you can explain why.

Ray's meta point [R]: the interface follows the loop. Inner-loop prompting lives in the terminal; outer-loop steering moves to Slack threads.

7Why it is a master class: Ray's lessons

  1. Verification is the new bottleneck. Ambition scales with how fast Claude can check its own work. [A][R]
  2. Decide how you will verify before you build. For a feature: acceptance criteria in the spec plus Playwright-style verifiers. For a migration: engineered signals. [R]
  3. Design the signal, not just the check. Checkpoints localize, fingerprints separate bugs, self-written requests reproduce, all without reading customer data. [A][R]
  4. Turn signals into loops the agent hill-climbs alone, and keep them simple so they scale with Claude's capability: agents chose hypotheses, reproductions and fixes; verifiers judged. [A][R]
  5. Put human judgment only into what counts as correct, and move people toward the outer loops. [A][R][O]
  6. Nest loops so each catches what the inner one misses: fast and imperfect (sandbox), slow and real (production), cumulative (memory). [A]

8Deeper reads and what to steal (analysis, beyond the sources)

  • Generator-verifier gap [A uses Sudoku]: the NP intuition. The team did not find a cheap check; they manufactured one where none existed.
  • Specification gaming: the web-search shortcut is Goodhart's law in miniature. A byte-match verifier is a proxy reward; seam review is the reward correction, the memory loop amortizes it.
  • Prior art: differential testing / shadow diffing (Twitter's Diffy, GitHub's Scientist). New here: record-and-replay of the stochastic core, text-free diffs, and agents that synthesize their own witness inputs, close to counterexample-guided search.
  • Masking: fingerprint A hid B and C, so the match curve is non-monotone (24% to 6.5% to 99.6%). Expect fixes to expose deeper layers.
  • Ray vs article, checked: early fixes were verified on staging test traffic (Ray says production); a bug produced "hundreds of thousands" of records (Ray: "hundreds or thousands"). Rollout fallback and 80/20 come from a podcast Ray cites, unverified here.

Steal for a solo AI project: build the oracle before the code; record and replay every stochastic call (LLM, clock, RNG); emit shape-only diff records and hash them into fingerprints; dispatch one agent per new fingerprint; make every correction a rule + backward sweep + lint.
