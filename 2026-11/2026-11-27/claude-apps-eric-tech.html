An artifact is the interactive page, chart, or tool Claude builds alongside a chat. Install as app gives that same artifact a desktop icon and its own window on Mac or Windows. Edits to the artifact update the installed app automatically. Eric’s argument is that the whole path from describing a tool to getting it onto someone’s desktop is now short enough to make one-off internal software practical. 0:23–1:30 · 2:19–3:03

Eric’s three catches

1. The app depends on Claude and the owner’s sharing settings

Launching requires an internet connection and a signed-in Claude Desktop session. If the owner stops sharing the artifact, your installed copy loses access. Eric’s practical rule is to keep the authoritative data somewhere you control and use the artifact as the interface. A team tracker, for example, can show or edit records from a source your team can still open if the artifact disappears. Building an app and any Claude calls it makes also use your plan allowance, according to the Help Center. 5:27–5:43 · Claude Help Center

2. Installation works on Mac and Windows

The beta covers Claude Desktop on macOS and Windows. The installed-app experience is unavailable on Linux, in a web browser, and on phones. That matters if the first thing you need is to enter an expense from your phone. If the artifact has a shareable browser version, test that separately on the device you actually intend to use. 5:43–5:50 · Claude Help Center

3. Anthropic does no pre-install safety review

Eric highlights what happens once an app gets full computer access. It can run programs and read, edit, or delete files without asking for each action. Anthropic says eligibility generally requires the app to be made by you or, on eligible Team and Enterprise setups, people in your organization. A shared link from outside your organization cannot be assumed eligible simply because you trust the sender. Use the lowest permission level that does the job. 5:50–6:12 · Claude Help Center

One limit of the update prompt. Claude asks again after an artifact update, even for your own edits. Code loaded from another site can change without triggering a new prompt. Revoking full access also leaves any file changes the app already made in place. 2:11 · Claude Help Center

Install and open a Claude App

  1. Build and test the artifact in chat. Eric starts with Anthropic’s example, a timer. Verify its basic behavior in the artifact preview before adding desktop features.
  2. Open the artifact in the main Claude Desktop window. Open the artifact title menu or right-click it, choose Install as app, then select Install. Anthropic also documents a route through Share.
  3. Launch it from your operating system. On Windows, look for Claude Apps in Start or use the desktop shortcut. On macOS, use Spotlight or open Claude Apps inside the Applications folder in your home folder.
  4. Allow only the desktop feature you need. A timer can work in its window at the default tier. Background notifications or a tray icon can request their own permissions. You can review grants while the app is open via File → Apps → Permissions in Claude Desktop.

The install flow uses your Claude account and needs no separate API key, packaging, or code signing. If the option is missing, Anthropic specifies Claude Desktop version 6.28899.0 or later, an eligible artifact, and the appropriate workspace settings. Claude Docs, Slides, Sheets, legacy artifacts, and live Claude Cowork artifacts are ineligible. Anthropic lists the beta across plans, with organization and deployment restrictions. 1:01–1:38 · Claude Help Center

Which tools Eric thinks this can replace

Eric’s candidates are a project tracker, a weekly numbers report, and an onboarding checklist. These have a narrow job and can be tailored to the team’s existing routine. He expects the small tools around a customer relationship management system or accounting platform to go first. Maintaining the core platform means keeping years of data usable and supporting many users over time. 3:03–3:38

A progressive web app (PWA) already made a website launchable from the desktop. Eric’s point is that Claude combines building the tool, hosting it, sharing it, saving data, and installing it in one workflow. A tool can earn its keep by saving a single team an hour a week without needing a broader market. 2:26–3:03 · 6:20–6:36

What’s next

For a first Windows pilot, try a weekly status report using sample data. This prompt applies Eric’s examples and data-ownership advice.

Build a weekly project status artifact that reads a CSV I upload. Summarize completed items, active work, and blockers, with a filter for project. Let me download the report as CSV. Keep the input file untouched and use the default permission tier.

Import the same sample twice, confirm that totals match the input, then open the downloaded report independently. Decide whether the pilot is worth keeping by measuring the time saved and checking that the underlying workflow is still usable if you lose access to the artifact.
