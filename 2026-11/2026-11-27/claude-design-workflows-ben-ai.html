Set up the design system first

Ben starts with a reusable specification for colors, typography, logo, and preferred components. With an existing brand, he gives Claude the website and asks it to extract the system. For a new look, he shortlists references and assigns each one a specific job, such as typography from one and a palette from another. He saves the result under Design Systems in Claude and describes invoking a packaged skill with /design system. Give fonts their own review before you start the first deliverable. Design-system method at 00:41

Copyable design-system prompt

Build an editable design system for [project] from [brand URL, logo, screenshots, and references].
For each reference, say which trait to borrow. Define color roles, type hierarchy and font fallbacks, spacing, component states, image treatment, and 3–5 concrete do/don’t examples.
Show a sample hero, button family, and content card so I can review the system. Save the approved version as a Claude design system and export a portable DESIGN.md.

Connect media generation when a project needs it. In Claude’s connector settings, add Higgsfield using https://mcp.higgsfield.ai/mcp and sign in. Model Context Protocol (MCP) lets Claude call external tools. Ask for your Higgsfield credit balance to test the connection before generating. Higgsfield says its MCP generations consume credits. 02:38–06:41

01. Build a landing page around the action

Ben’s AI Accelerator page starts with four inputs to Fable 5.2: the design system, structural references, the page goal, and copy direction. He uses the brand system for the look and reference pages to place the hero, proof, and call to action. In his example, the action is joining the Accelerator. Chapter · Prompt ingredients

  1. Set the page goal. Supply the audience, offer, one primary call to action, and verified proof. Bring a full-page reference from Lapa Ninja and, if helpful, a component from 21st.dev. Name what each reference contributes. Ask Claude to study how five peers frame the offer and use the patterns to draft original copy.
  2. Compare before polishing. Ask for two or three canvas variants with different hero or proof placement. Choose one and use the Impeccable skill to audit hierarchy, spacing, typography, and accessibility. Canvas and audit · Impeccable
  3. Storyboard scroll behavior before generating media. Ben turns the Accelerator’s features into a Claude-style checklist. As the user scrolls, items are checked off, the mascot changes, and the last beat leads to the Join action. He uses Higgsfield for the hero animation and mascot imagery, including GPT Image 2.6 for the still. Scroll sequence

Copyable landing-page prompt

Build a responsive landing page for [product], for [audience], with one primary action: [CTA].
Apply my attached design system. Use [full-page reference] for section order and [component reference] for [specific element]. Study how up to five relevant competitors explain their offers, then draft original copy using only the claims and proof I supply.
Show 3 variants in an editable canvas. For each, label the hero, proof, and CTA. After I choose, audit typography, spacing, keyboard focus, contrast, and mobile layout. If the page needs scroll animation, storyboard the beats and show a static fallback before generating any media.

Ready to ship when the offer and main button make sense on a phone, links work, and every step in the scroll story has a readable reduced-motion equivalent.

06:42–10:10

02. Turn a feature map into a product demo

For Baalda, a shared team knowledge app, Ben aims for a 45–60 second film for small and midsize businesses that use AI. The brief foregrounds team syncing and shared context. Claude uses screenshots to rebuild the relevant app screens in code, so it can animate the specific interactions. Ben also shows Baalda’s onboarding tutorial page and describes adding narration and sound effects. Chapter · Feature map and interface reconstruction

  1. Pick one audience and a short feature path. Give Claude one or two references for pacing, the intended tone, and a map of feature → screen → action → visible outcome. For example, shared notes → workspace → teammate opens a note → edit appears for both users. Ben suggests Product Hunt and Product Video Examples for software, and Meta’s Ad Library for physical-product ads.
  2. Approve the storyboard with your real product in view. For software, supply screenshots or a demo instance with sample data. For physical goods, start from real product photos and use image generation for studio-style treatments as needed. Preserve labels, geometry, colors, and the features the buyer will actually get. Physical-product branch
  3. Add sound and supporting footage to the approved cut. Ben suggests ElevenLabs for narration and music, and Higgsfield’s video models for supporting footage or ads. He says he offloads rendering to Higgsfield’s cloud computer. Check current render and generation terms before budgeting. Audio and rendering

Copyable product-demo prompt

Plan a 45–60 second demo for [product], for [audience] who struggle with [pain]. Use my brand system and these pacing references: [links].
Use these feature-to-screen mappings: [feature | screen or screenshot | action | visible result]. Show the two or three most important features. For a physical product, use the supplied product photos to lock its appearance.
Output a timed storyboard with narration, visuals, on-screen text, and source assets. Flag missing evidence and any generated footage. Wait for approval, then animate the approved screens and propose audio. Deliver a preview and export settings for [channel].

Ready to ship when viewers can identify the problem and the resulting product action, all UI claims match the real app, and narration stays intelligible over music at phone volume.

10:11–13:49

03. Generate social visuals in batches you can review

Ben feeds Claude a design system, brand assets, relevant high-performing visuals, and the message he wants readers to understand. For his video about Claude’s Dream feature, he shares the script and 3D logo references, asks for 50 thumbnail ideas and uses GPT Image 2.6 through Higgsfield. In his live artifact, an interactive output inside Claude, he selects two numbered options and asks for five variants of each. Chapter · Dream example

  1. Separate the communication goal from the layout. Provide a script or one-sentence message and tell Claude what someone should grasp at a glance. Supply your own past winners and the brand assets it should preserve.
  2. Choose the output surface based on the material. Use an editable canvas for text, geometry, and simple illustrations in carousels, infographics, or ads. Use a numbered gallery for photorealistic or detailed 3D imagery generated by Higgsfield. Ben also compares the same ideas across image models to see what each produces. Model and output choices
  3. Explore broadly, then refine the finalists. Ben generates up to 50 thumbnail options. A lower-credit adaptation is to ask for 30–50 written concepts, select 6–10 to render, then iterate on your top two. Judge thumbnails at feed size and judge a carousel as a sequence.

Copyable social-visual prompt

Create [thumbnail, carousel, infographic, or ad] for [platform and dimensions]. In one glance the audience should understand [message]. Use [script/data], my design system, and [brand assets and past high performers].
Give me [N] distinct numbered concepts across different hooks and compositions. Place editable, text-led designs on a canvas. For generated imagery, show the estimated credit cost if available, wait for my shortlist, then make a numbered gallery with the approved model and references. Keep a record of the prompt and model for each winner so we can refine it by ID.

Ready to ship when the idea survives feed-size viewing, key text remains inside the platform’s safe area, and any product or factual claims match your source material.

13:50–17:25

04. Edit and animate against a word-timed transcript

Ben builds a separate design system for video. He feeds Claude the raw footage and audio, uses Whisper to attach timestamps to individual words, and has Claude remove pauses and mistakes. Before animation, Claude makes an interactive storyboard that places each planned visual beside its line of narration. Ben’s team asks for two or three choices per beat and comments on the storyboard. Chapter · Transcription and storyboard

  1. Define the motion language. Bring sample clips or motion references and specify titles, lower-thirds, transitions, animation tempo, and caption style. Include target aspect ratio and where titles, faces, and graphics can safely sit.
  2. Transcribe, edit, and retime. Use Whisper with word timestamps, propose cuts, and align every animation cue to the edited timeline. Keep source and edited timecodes in the cut list or transcribe the approved cut again to prevent timing drift. Whisper transcription options
  3. Approve a storyboard before animating. Give each scene a start time, narration fragment, visual, motion cue, and asset reference. Make alternatives visible on the same canvas or artifact and approve a choice per beat.
  4. Preview, then render. Ben asks for Opus 5.5 subagents where he can select them to control Fable usage. He previews the animated composition in HyperFrames Studio. He also shows a finished short with supporting footage, lighting, and background changes from Higgsfield. Animation, preview, and enhancements · HyperFrames Studio

Copyable motion-graphics prompt

Edit this [raw video and audio] into [length and aspect ratio], using [motion design system and references].
Transcribe with word-level timestamps. Propose cuts for mistakes and long pauses. Preserve the original and map original timestamps to the edited timeline.
Create a live storyboard with beat ID, edited time range, exact narration cue, frame mockup, motion, and asset source. Give me 2 options for key beats. Wait for approval before animating.
After approval, preview the HTML composition in HyperFrames Studio. Check cue timing, caption accuracy, safe areas, and audio levels. Export the edited video after I approve the preview.

Ready to ship when captions match the final audio, graphics arrive on the intended words, the cut makes sense without the graphics, and the exported file matches the preview.

Save the approved workflow as a skill

Ben recommends using Fable for an exploratory run, then turning a result you like into a reusable skill. He describes running the skill on Opus and, for recurring video work, potentially Sonnet. His thumbnail skill takes a new video script and reuses the brief, model, and gallery approach. Model-cost strategy · Saving the video workflow

Copyable skill handoff

Turn this approved workflow into a Claude skill. Capture required inputs, design-system reference, decision points, model and connector choices, preview format, approval gates, failure recovery, and final acceptance checks.
Include the smallest working example, one approved output as a reference, and any budget defaults. Run a new brief on the cheaper model available to me and compare the result with the approved reference using the same checks.

What’s next

Try the four formats on one small launch. Use the same offer, design system, and product evidence throughout. Track how many concepts survived review, how many paid generations you used, and how long it took to get an approved output. That gives you a concrete baseline for testing whether a reusable skill pays off on the second launch.
