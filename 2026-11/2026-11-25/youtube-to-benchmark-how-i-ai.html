I recorded the category, task, weight, score for each requested model, task brief, and an outcome note. I tracked Astra and Sol separately, giving four named columns for 25 rows.

Coverage check. 2 writing + 2 coding + 4 assistant + 8 creative + 4 video + 5 apps = 25. I also checked that all 25 task titles were distinct.

Turn visible evidence into task briefs

The review screen showed a collapsed field for the original model prompt. I used the visible judging criteria and spoken task description where available. For entries with only a visible task title, I kept the brief narrow and identified missing inputs or outputs.

Capture the outputs and assemble the PDF

  1. Pause where the selected model is visible. I captured stills of the outputs the episode actually showed, then cropped to the relevant scorecard, rubric, or output. A still documents what the output looked like at that moment. The timestamp lets readers judge motion and interaction in the episode.
  2. Keep test variants distinct. Bringing an existing illustration to life and painting an entirely new page occupy separate score rows. The former let models reuse a method. The latter required their own illustration, lighting, and motion decisions. Existing page · New page
  3. Generate the document from structured rows. Python held the score data and briefs. Pillow cropped the stills and obscured personal details in selected previews. ReportLab laid out the tables, galleries, page numbers, and clickable timestamps. Task and category scores came from the published dashboard.
  4. Preserve the scoring context. The dashboard used 70% presenter scoring and 30% model judges, with app prototypes scored by the presenter alone. Task weights were 3× for substantial, 2× for medium, and 1× for tactical. The separate annoyance analysis measured interaction friction in prior sessions. Leaderboard · Annoyance dashboard

Verify data, links, and page layout

  • Data. I checked the task count and uniqueness before rendering, then extracted the finished PDF text and verified that all 25 titles appeared.
  • Links. The final PDF contained 29 clickable timestamp links. I checked that each targeted the same YouTube video with a time offset.
  • Layout. I rendered pages to images and inspected the results. The first draft pushed some scorecards onto nearly empty pages. I regrouped the tables and screenshots, then rendered and checked the finished 10-page document.
  • Evidence limits. The report includes score evidence for every task and output stills for the demonstrated examples. Exact prompt text and many individual outputs were unavailable in the public material I could verify.

What’s next

For a repeatable video-to-report workflow, give each score row a timestamp and each task brief an evidence label. When a publisher releases the underlying prompts or benchmark data, those labels show exactly which entries can be upgraded from screen-based observations to reproducible test cases.
