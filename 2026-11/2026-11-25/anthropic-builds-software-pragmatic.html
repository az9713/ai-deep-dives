Introduction

Gergely Orosz introduces Katelyn Lesse, who leads Claude Platform engineering at Anthropic. They discuss an AI-assisted rewrite of the Messages API, selective human review of agent-written code and a hiring process that puts candidates in front of coding agents.

03:09

From Betterment to Stripe

Lesse switched from chemical engineering to computer science after an introductory course. At Betterment she joined a small team building a 401(k) product and moved into management while still building and reviewing code. She later joined Stripe Capital, the lending business, drawn by Stripe’s engineering standards and the pace at which it built new financial products.

07:04

How the Claude API works

Claude Platform sits between the applications and the inference layer, where models run on accelerators such as GPUs and TPUs. A request passes through authentication and authorization, then reaches a CPU-based service that handles tokenization, billing and safety checks. Tokens flow back through that service to the caller. The same Messages API serves Anthropic’s apps and external developers. Streams can stay open for up to about an hour, and a stateless API requires callers to send conversation state with each turn.

10:21

Why the team rewrote the Messages API in Rust

Python made sense when a small team spanning research and product first built the API. As traffic surged, CPU capacity in the original single-region setup became a constraint. Anthropic added regions and found smaller efficiencies before choosing Rust for performance and memory safety. Claude wrote implementation code and helped engineers learn the language as they worked. Lesse saw Rust’s compile-time checks as especially valuable because an agent can iterate on compiler feedback before a human gets involved.

23:40

How shadow traffic verified the rewrite

The team pivoted from porting individual components to building a parallel Rust version. A thin Python front door served live requests through the existing system and sent copies through the Rust version. Privacy rules barred engineers from inspecting customer prompts or completions, so they checked what was passed to inference and compared outgoing token counts. They drove mismatches down over time, began routing live requests to Rust with Python as a fallback, and removed the front door once confident. Lesse’s rough estimate was that engineers skipped deep line-by-line reading on about 80% of the agent-opened pull requests in this migration. They dug into the code where mismatches and other issues demanded it.

31:11

Onboarding with Claude and finishing the migration

New engineers ask Claude to explain the system from the codebase and internal sources connected through Model Context Protocol (MCP) servers. Claude can turn that context into a walkthrough or an interactive architecture diagram. Lesse estimates the Rust migration took about five to six months, including early investigation, with a small core team. Meanwhile, other teams kept shipping to Python. When a feature became generally available and triggered a spike in mismatches, the migration team added static checks that required new work to land in both versions for the final stretch.

44:35

Building Claude Managed Agents

The first design booted Claude Code inside a sandbox for every agent. A sandbox failure could kill the agent, startup added latency, tool credentials risked ending up inside the sandbox, and each running sandbox consumed CPU. The team moved the harness, which runs the agent’s control loop, onto a durable server. They stored session state separately and started sandboxes as work required them. A proxy injects credentials into outgoing requests from a separate vault. Lesse says the redesigned system averaged about one-third the CPU use of the original design. The team used Go for this project and built the underlying architecture for both Claude Code’s cloud experience and API customers.

How engineering teams work

Lesse describes small teams of roughly five to ten people that know and operate their own systems. They skew more senior because engineers spend more time designing systems and coordinating across teams. Engineers use Claude Code and Cowork for interactive work, and much of the collaboration with cloud agents happens in Slack. Claude’s permissions can vary by context, such as a channel or direct message.

What agents handle on their own

Engineers increasingly delegate a project or outcome that spans multiple pull requests. Agents can create follow-up tasks, post progress in Slack and ask for a decision when blocked. Some routine changes can go all the way to deployment after automated classification and review. Examples include software development kit (SDK) version bumps and repairs to flaky tests that make continuous integration (CI) fail.

How human code review is assigned

A Claude-based classifier runs on each change in the workflow Lesse describes. It decides whether to call in a human, how many reviewers are needed and which teams should look. A routine change can merge automatically when Claude verifies the intended outcome. Riskier changes, changes with possible side effects and changes to systems where the team still wants oversight go to humans. Lesse describes automatic merging as covering a small but growing set of change types.

Claude on call

After shadowing the API on-call rotation for months, Claude began receiving alerts first to distinguish noise from actionable pages. A real alert is escalated to a human. While the person responds, Claude can investigate and propose a fix, and may begin work toward it. Lesse describes unattended resolution of real incidents as a goal. The current workflow mainly filters noise and gives people a head start on diagnosis.

A product manager ships to production

A technical product manager worked with Claude in Slack to build a prompt-cache diagnostics dashboard for the developer console. The dashboard helps developers understand cache hit rates. The API also exposes reasons for some cache misses. Engineers were available for review, and the developer experience team still owns the console and would be paged if it broke. Lesse draws the current boundary at changes to the core API, where she would still expect engineers to lead.

Anthropic’s software factory

Lesse says the label is uncommon internally, but describes agents writing, verifying, reviewing and deploying changes, then monitoring software in production. One experiment uses a persistent quality-assurance agent to check a system against a description written by humans and propose fixes. Central Developer Acceleration builds shared infrastructure such as the Scion source-control system. Platform Acceleration builds team-specific workflows, including test repair. Individual engineers also build tools for bottlenecks they encounter, such as a Slack channel for coordinating multiple agents around a shared goal.

Why traditional coding interviews are being phased out

Hand-coding performance had become a weaker signal for teams whose day-to-day work uses agents. Some candidates struggled in the coding round and did well in technical design and other rounds. Anthropic is experimenting with asking candidates to review agent-written code or designs or to build something with an agent. Technical design and discussions of past work continue. The team is still working out which exercises produce useful, consistent and fair assessments.

Levels, promotions and performance reviews

Lesse says Anthropic still uses numeric levels, promotions and performance reviews. Hiring skews more senior, and elapsed time has become a weaker proxy for the complexity of a project. The measures she points to are impact, such as CPU and latency improvements, and the quality of cross-team coordination. She prefers giving feedback in real time and says peer feedback at Anthropic is mostly transparent.

The software engineer identity crisis

Lesse understands why engineers who enjoyed the craft of writing code feel a loss. She sees room for greater ambition, from improving everyday software to building systems where many agents can work together. That work depends on engineering fundamentals such as identity, security, infrastructure and reliable coordination. Her advice is to learn with agents while developing deep expertise in the problems that grow harder as their scope expands.

Book recommendation

1:48:12

Orosz’s closing takeaways

Orosz highlights Rust’s efficiency and compiler feedback, hiring experiments that could introduce more subjectivity, the product manager’s deployment and Claude-based onboarding. He points out that the onboarding example depends on Claude having access to the codebase and relevant internal systems. He treats Anthropic’s product-manager example as an observation and questions how widely it will transfer.

What’s Next

Try the migration pattern on a small service. Before asking an agent to write a replacement, pick three observable behaviors that must match, replay the same recorded inputs against both versions, and deliberately introduce a regression. The test of your verifier is whether it catches the regression and tells you where to look.
